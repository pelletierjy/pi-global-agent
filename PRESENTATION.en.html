01 · Foundations

Three bricks, one equation

Each agent is a Pi Durable harness running inside a Durable Object, exposed by a Worker.

Pi Durable (the harness)

Runs agent conversations with the golden rule: everything is committed to disk BEFORE it executes. Every step = a task + checkpoint → crash resume, exactly-once (requestId), automatic compaction.

Durable Object (the disk)

A stateful micro-server with its own SQLite that only exists when called (~$0 at rest) and survives everything: redeploys, crashes, weeks without a request.

Worker (the façade)

HTTP layer: Bearer AGENT_TOKEN auth, routing to the DO, cross-worker federation, weekly cron, static dashboard.

The equation
Pi Durable inside a Durable Object = a persistent agent, reachable anywhere, that loses nothing

06 · In production

4 operational scenarios

All four are live right now (PRs merged, workers deployed).

C

Weekly sweep

Hub cron Mon 13:00 UTC: digests every peer's queue into a durable note + dispatches SWEEP_TASK (deduplicated). Manual: POST /federation/sweep.

D

Realtime dashboard

/dashboard: 5 cards (state, queues, notes, model) refreshed every 2 min (paused on hidden tabs) + live WS feed, auto-reconnect.

E

Real execution

The model calls run_command / read_file / write_file → exec_requests → runner.mjs executes in your repos (files confined to the project root).

B

Morning brief

node scripts/morning.mjs: fleet states + open tasks → the hub writes a prioritized brief and saves it with add_note. Built-in retries.

07 · Full example

From command to brief

The typical morning path — copy-paste as-is (env vars already set on the machine).

0 · once: the environment
# already set as user environment variables
$env:PI_AGENT_URL  = "https://pi-global-agent.need-homework.workers.dev"
$env:PI_AGENT_TOKEN = ""
# shortcuts used in every example below:
$base = $env:PI_AGENT_URL   # target worker (hub or project)
$H = @{ authorization = "Bearer $env:PI_AGENT_TOKEN" }  # auth, required everywhere
1 · talk to an agent (durable conversation)
Invoke-RestMethod -Headers $H -Method Post `
  -Uri "$base/conversations/root/messages" `
  -ContentType 'application/json' `
  -Body '{"content":"Hi, summarize the project"}' `
  -TimeoutSec 300
#  ^ POST = send a message
#  ^ "root" = the agent's main conversation
#  ^ wait for the model's answer (~2 s)
#  → { "status":"done", "text":"…" }   done = the model answered
2 · durable memory (every future session reads it)
Invoke-RestMethod -Headers $H -Method Post -Uri "$base/notes" `
  -ContentType 'application/json' `
  -Body '{"body":"limits live in models/constants.ts"}'
#  ^ POST /notes : append-only, never overwritten
Invoke-RestMethod -Headers $H "$base/notes?limit=5"
#  ^ GET : last 5 notes, from any machine
3 · morning brief (scenario B)
node D:\Repos\pi-global-agent\scripts\morning.mjs
#  1) table of all 5 peers (state, queues, notes)
#  2) list of open tasks across the fleet
#  3) the hub writes a prioritized brief (FR)
#  4) it saves the brief with its add_note tool
# model hiccup? built-in retry ×3
node ...\morning.mjs --no-ask   # raw data, no model call
4 · task queue: add → claim → done
Invoke-RestMethod -Headers $H -Method Post -Uri "$base/tasks" `
  -ContentType 'application/json' -Body '{"title":"Fix flaky test"}'
#  → {id:1, status:"pending"}  (from any machine)
$task = Invoke-RestMethod -Headers $H -Method Post "$base/tasks/claim"
#  ATOMIC claim: pending → in_progress (single SQL statement)
Invoke-RestMethod -Headers $H -Method Post "$base/tasks/$($task.id)" `
  -ContentType 'application/json' `
  -Body '{"status":"done","result":"fixed: mocked the timeout"}'
#  always close with done/failed + an explicit result
5 · let the AGENT really code (scenario E)
node D:\Repos\pi-global-agent\runner.mjs
#  once per session: local executor (outbound polling, no open port)
#  STOP it before any `wrangler deploy`, restart after !
Invoke-RestMethod -Headers $H -Method Post `
  -Uri "https://pi-conversia-core.need-homework.workers.dev/conversations/root/messages" `
  -ContentType 'application/json' `
  -Body '{"content":"Call run_command: git status then summarize"}' -TimeoutSec 300
#  model → run_command → exec_requests (DO waits) → runner executes
#  → result flows back → the model answers with the real output

10 · Operations

Golden rules & links

What to remember to run the fleet without surprises.

⚠Stop the runner before wrangler deploy, restart it after — its polling keeps the Durable Objects alive, and DOs only load new code on restart.
🧮Free quota (~100k req/day, resets 00:00 UTC): runner idle = 1 claim/worker/30 s (PI_POLL_MS), dashboard every 2 min (paused on hidden tab). HTTP 429 / error 1027 = quota spent → wait it out, do not hammer.
🔑One AGENT_TOKEN for all 5 workers (same value as secret and in .dev.vars); PI_AGENT_URL/PI_AGENT_TOKEN already set as user env vars.
🧠Models: default google/gemini-3.8-flash (reliable); "free" tiers are flaky (404/429/503) — morning.mjs retries built-in.
🗓Hub cron: Mondays 13:00 UTC (triggers.crons) = same logic as POST /federation/sweep.
🌐jyp.solutions: domain not taken → status quo .need-homework.workers.dev; the routes config stays commented, ready if a zone ever arrives.
📦Delivered: 10 PRs merged · release v1.3.4.0 (MSI + SHA256) · dashboard, sweep, runner, morning brief all operational.
