01 · Fondations

Trois briques, une équation

Chaque agent = un Pi Durable exécuté dans un Durable Object, exposé par un Worker.

Pi Durable (le harness)

Exécute les conversations d'agent avec la règle d'or : tout est commité sur disque AVANT d'être exécuté. Chaque étape = task + checkpoint → reprise après crash, exactly-once (requestId), compaction auto.

Durable Object (le disque)

Micro-serveur étatful avec son SQLite, qui n'existe qu'à la demande (≈0 € au repos) et survit à tout : redéploiement, crash, semaines sans requête.

Worker (la façade)

HTTP : auth Bearer AGENT_TOKEN, routage vers le DO, fédération inter-workers, cron hebdo, dashboard statique.

L'équation
Pi Durable dans un Durable Object = un agent persistant, partout accessible, qui ne perd rien

06 · En production

4 scénarios opérationnels

Tous les quatre tournent actuellement (PRs mergées, workers déployés).

C

Sweep hebdomadaire

Cron lun. 13h UTC sur le hub : digest des files de tous les peers → note durable + dispatch de SWEEP_TASK (dédupliqué). Manuel : POST /federation/sweep.

D

Dashboard temps réel

/dashboard : 5 cartes (état, files, notes, modèle) rafraîchies toutes les 2 min (pause si onglet masqué) + feed WS live, reconnexion auto.

E

Exécution réelle

Le modèle appelle run_command / read_file / write_file → exec_requests → runner.mjs exécute dans vos dépôts (fichiers confinés à la racine).

B

Brief du matin

node scripts/morning.mjs : états + tâches ouvertes de la flotte → le hub rédige un brief priorisé (FR) et l'enregistre via add_note. Re-essais intégrés.

07 · Exemple complet

De la commande au brief

Le parcours typique du matin — copier-coller tel quel (env déjà posé sur la machine).

0 · une fois : les variables
# déjà posées en variables utilisateur

$env:PI_AGENT_URL  = "https://pi-global-agent.need-homework.workers.dev"

$env:PI_AGENT_TOKEN = ""

# raccourcis réutilisés dans tous les exemples :

$base = $env:PI_AGENT_URL   # worker cible (hub ou projet)

$H = @{ authorization = "Bearer $env:PI_AGENT_TOKEN" }  # auth, obligatoire partout
1 · parler à un agent (conversation durable)
Invoke-RestMethod -Headers $H -Method Post `

  -Uri "$base/conversations/root/messages" `

  -ContentType 'application/json' `

  -Body '{"content":"Salut, résume le projet"}' `

  -TimeoutSec 300

#  ^ POST = on envoie un message

#  ^ "root" = la conversation principale de cet agent

#  ^ on attend la réponse du modèle (~2 s)

#  → { "status":"done", "text":"…" }   done = le modèle a répondu
2 · mémoire durable (toute future session la lit)
Invoke-RestMethod -Headers $H -Method Post -Uri "$base/notes" `

  -ContentType 'application/json' `

  -Body '{"body":"limites = models/constants.ts"}'

#  ^ POST /notes : append, jamais écrasé

Invoke-RestMethod -Headers $H "$base/notes?limit=5"

#  ^ GET : les 5 dernières notes, de n'importe quelle machine
3 · brief du matin (scénario B)
node D:\Repos\pi-global-agent\scripts\morning.mjs

#  1) table des 5 peers (état, files, notes)

#  2) liste des tâches ouvertes de la flotte

#  3) le hub rédige un brief priorisé (FR)

#  4) il l'enregistre via son outil add_note

# échec modèle ? re-essai automatique x3

node ...\morning.mjs --no-ask   # mêmes données, sans appel de modèle
4 · file de tâches : add → claim → done
Invoke-RestMethod -Headers $H -Method Post -Uri "$base/tasks" `

  -ContentType 'application/json' -Body '{"title":"Fix flaky test"}'

#  → {id:1, status:"pending"}  (n'importe quelle machine)

$task = Invoke-RestMethod -Headers $H -Method Post "$base/tasks/claim"

#  prise ATOMIQUE : pending → in_progress (1 seule requête SQL)

Invoke-RestMethod -Headers $H -Method Post "$base/tasks/$($task.id)" `

  -ContentType 'application/json' `

  -Body '{"status":"done","result":"test réparé: mock du timeout"}'

#  toujours fermer avec done/failed + un résultat explicite
5 · laisser l'AGENT coder (scénario E)
node D:\Repos\pi-global-agent\runner.mjs

#  1x par session : exécuteur local (polling sortant, aucune porte ouverte)

#  STOP avant tout "wrangler deploy", relance après !

Invoke-RestMethod -Headers $H -Method Post `

  -Uri "https://pi-conversia-core.need-homework.workers.dev/conversations/root/messages" `

  -ContentType 'application/json' `

  -Body '{"content":"Appelle run_command: git status puis résume"}' -TimeoutSec 300

#  modèle → run_command → exec_requests (DO attend) → runner exécute

#  → résultat remonté → le modèle répond avec le vrai résultat

10 · Exploitation

Règles d'or & liens

Ce qu'il faut retenir pour exploiter la flotte sans mauvaise surprise.

⚠Stopper le runner avant wrangler deploy, le relancer après — son polling empêche les DO de redémarrer, or ils ne chargent le nouveau code qu'au redémarrage.
🧮Quota gratuit (~100k req/j, reset 00:00 UTC) : le runner idle = 1 claim/worker/30 s (PI_POLL_MS), dashboard 120 s (pause onglet masqué). HTTP 429 / error 1027 = quota épuisée → patienter, ne pas hammer.
🔑Un seul AGENT_TOKEN pour les5 workers (identique en secret et en .dev.vars) ; PI_AGENT_URL/PI_AGENT_TOKEN déjà posés en variables utilisateur.
🧠Modèles : défaut google/gemini-3.8-flash (fiable) ; les tiers « free » sont instables (404/429/503) — re-essais intégrés dans morning.mjs.
🗓Cron hub : lundi 13h UTC (triggers.crons) = même logique que POST /federation/sweep.
🌐jyp.solutions : domaine non pris → statu quo .need-homework.workers.dev ; config routes commentée, prête si une zone arrive.
📦Livré : 10 PRs mergées · release v1.3.4.0 (MSI + SHA256) · dashboard, sweep, runner, brief opérationnels.

Les 4 gestes du quotidien

Toute la flotte tient là : le matin, la mémoire, une question, une délégation.

1 · LE MATIN

node scripts\morning.mjs

Brief priorisé en français sur les 5 agents (re-essais automatiques).
--no-ask = données brutes, sans appel de modèle.

2 · EN QUITTANT

POST /notes

{"body":"ce que j'ai compris…"}
Mémoire permanente : toute future session la relit avec GET /notes.

3 · UNE QUESTION

POST /conversations/root/messages

{"content":"Résume scalesviewer"}
Réponse en ~2 s → {status:"done", text:"…"}.

4 · DÉLÉGUER

add → claim → done

add "…" n'importe où → la session pi du projet claim, ferme par done "résultat".
